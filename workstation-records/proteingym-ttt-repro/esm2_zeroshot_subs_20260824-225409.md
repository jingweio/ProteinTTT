# proteingym-ttt-repro — experiment record  (created 2026-08-24 22:54; status: PLANNED)

复现 **ProteinTTT (ICLR 2026) Table 2** 的 protein fitness prediction 结果：在 **ProteinGym v1.3
DMS substitutions zero-shot** 上，量化 test-time training 对 ESM2 的增益。

---

## 1. Goal / hypothesis

**要复现的具体数字**（paper Table 2，Avg. Spearman）：

| row | Avg. Spearman | Activity | Binding | Expression | OrganismalFitness | Stability |
|---|---|---|---|---|---|---|
| ESM2 (35M) | 0.3211 | 0.3137 | 0.2907 | 0.3435 | 0.2184 | 0.4392 |
| **ESM2 (35M) + ProteinTTT** | **0.3407 ± 0.00014** | 0.3407 | 0.2942 | 0.3550 | 0.2403 | 0.4733 |
| ESM2 (650M) | 0.4139 | 0.4254 | 0.3366 | 0.4151 | 0.3691 | 0.5233 |
| **ESM2 (650M) + ProteinTTT** | **0.4153 ± 0.00003** | 0.4323 | 0.3376 | 0.4168 | 0.3702 | 0.5195 |

**Hypothesis under test:** ProteinTTT 报告的增益 **+0.0196 (35M) / +0.0014 (650M)** 在独立实现的
harness 上可复现，且方向/量级与 paper 一致。

**⚠️ 开工前已确认的一件事（决定了整个实验设计）：**
paper 的两行 **baseline 不是作者重算的，而是直接取自 ProteinGym leaderboard**。
我用本 repo 内 `refs/DMS_substitutions_Spearman_DMS_level.csv`（ProteinGym 官方发布的 per-assay
Spearman）跑官方 aggregation，得到：

| | 我从官方 CSV 聚合 | paper Table 2 | Δ |
|---|---|---|---|
| ESM2 (35M) | 0.3208 | 0.3211 | −0.0003 |
| ESM2 (650M) | 0.4138 | 0.4139 | −0.0001 |
| SaProt (650M) | 0.4566 | 0.4569 | −0.0003 |
| ProSST (K=2048) | 0.5069 | 0.5068 | +0.0001 |

per-category 除 `OrganismalFitness` 外**逐位完全相同**（如 ESM2-650M：Activity 0.4254、
Binding 0.3366、Expression 0.4151、Stability 0.5233 全部对上）；OF 差 0.0008–0.0014，方向不一致
（ProSST 反而偏高），推测是 paper 用的 ProteinGym 版本与本地 v1.3 之间某个 OF assay 有更新。

**这个 0.0003–0.0014 的 benchmark-version 噪声底，和 ESM2-650M 声称的增益 +0.0014 同量级。**
⇒ 650M 这一行**在统计上不是一个可判定的复现目标**；35M 的 +0.0196 是它的 14×，才是真正
可证伪的目标。这直接决定了下面的优先级。

## 2. Design & decision points

### 2.1 三段式设计（S0 是硬 gate）

- **S0 — harness validation gate（无 TTT）。**
  用自己写的 `scripts/eval_proteingym.py --mode baseline` 从原始 assay CSV 重算 ESM2 的
  masked-marginals 分数，与 ProteinGym **发布的 per-assay Spearman 逐 assay 比对**。
  **通过条件：** 217 个 assay 全部 `|Δ| < 0.01`，且聚合后 Avg. Spearman 复现 0.3208 / 0.4138。
  **S0 不过就不跑 S1** —— 否则 TTT 的 delta 无法与 harness bug 区分。
- **S1 — TTT（5 seeds）。** `--mode ttt --seed 0..4`，每个 assay 跑 `model.ttt(seq)` 后重新打分。
- **S2 — 聚合。** `scripts/aggregate_proteingym.py` 实现 ProteinGym 官方口径，输出 Table-2 式表格
  + Table A4 的 MSA-depth 分层。

### 2.2 KEY DECISIONS（选了什么 + 为什么）

| 决策 | 选择 | 理由 |
|---|---|---|
| **复现哪几行** | ESM2 (35M) **主**，ESM2 (650M) **次** | 这两行是 repo 里**唯一 ship 了官方 TTT config** 的（`DEFAULT_ESM2_35M_TTT_CFG` / `DEFAULT_ESM2_650M_TTT_CFG`）。SaProt 需要 foldseek 3Di tokens、ProSST 需要自己的 structure tokenizer + AF2 structures、ProGen2-large 是 2.7B —— 都要额外一整套数据/依赖，不属于"复现这个 repo"的最小闭环。35M 增益最大（+0.0196）⇒ 最可证伪。 |
| **scoring 口径** | ProteinGym `masked-marginals` log-odds ratio（Eq. 6），`offset_idx=1`，`mutant_col="mutant"`，fp32，逐位置 mask，`L+2>1024` 时用 `get_optimal_window` | 逐行转写自 `ProteinGym/proteingym/baselines/esm/compute_fitness.py`。**唯一改动：把共享同一 window 的位置 batch 起来**（数学等价，纯速度）。等价性不靠断言，靠 S0 实测。 |
| **metric 实现** | 聚合用 `scipy.stats.spearmanr`（与 ProteinGym 一致）；eval 脚本里 `pandas.corr` 只用于进度日志 | 权威数字只能来自官方口径的那条路径。 |
| **aggregation** | per-assay ρ → `groupby(UniProt_ID, coarse_selection_type).mean()` → `groupby(coarse_selection_type).mean()` → 5 类取均值 | ProteinGym README 明确说 **不是 217 个 assay 的算术平均**，要校正每个蛋白的 assay 数与 function group。已用官方 CSV 验证这条路径能复现 leaderboard 数字（§1 表）。 |
| **seed 语义** | `ttt_generator.manual_seed(seed*1000003 + crc32(DMS_id))`，每个 (seed, assay) 独立 | paper 只说 "5 random seeds"。派生式 seeding 让**单个 assay 可以单独重跑并 bit-for-bit 复现**，同时避免等长 assay 之间 mask 相关。 |
| **每个 assay 都重算 pre-TTT 分数** | 是（`score_pre_ttt` 列在 ttt 模式下也写） | 额外 ~15% 开销，换来一个免费的正确性 guard：5 个 seed 的 `score_pre_ttt` 必须**完全一致**，否则说明 `ttt_reset()` 没有真正复原权重（base.py 的 `_ttt_get_state` 只遍历 `named_children()`，是个真实的风险点）。 |
| **TTT 超参** | 一律用 repo 里 ship 的 config，不调 | 复现 ≠ 调参。35M: `lr=4e-4, batch_size=4, ags=16, steps=30`；650M: `lr=4e-5, batch_size=4, ags=4, steps=30`；两者 `loss_kind=unnormalized_cross_entropy, optimizer=sgd(momentum=0), mask_ratio=0.15, crop_size=1024`。与 paper Table A3 / Figure A9 一致。 |
| **confidence function** | 不启用（`score_seq_kind=None`, `_ttt_eval_step` 用基类默认） | Table A3 的 fitness 行 "Steps (Conf. func. c)" 只写 30，没有括号里的 conf func —— fitness 任务固定跑满 30 步、取末步权重。代码路径上 `confidence=None` ⇒ `best_state` 不触发。 |

### 2.3 🔴 复现过程中发现的 upstream bug —— `ttt_reset()` 会破坏 ESM2 的 weight tying

**现象。** 我在 harness 里加了一个 O(1) 的 reset guard（所有参数的平方和 fingerprint，reset 后必须
逐位相等）。它在**第一个 assay 就报警**：fingerprint 从 396612.8596 变成 396876.7791。

**根因。** `TTTModule._ttt_set_state()`（`proteinttt/base.py`）对每个 child module **各自独立地**
`copy.deepcopy`。而 fair-esm 的 ESM2 **把 `lm_head.weight` 和 `embed_tokens.weight` 绑成同一个
tensor**（35M：202 vs 203；650M：538 vs 539，`remove_duplicate=False` 下多出来的那一个就是它）。
独立 deepcopy 之后两者**变成两个数值相同但彼此独立的 tensor**。

**为什么这不是无害的。** `ESM2TTT._ttt_get_frozen_modules()` 返回 `[self.embed_tokens]`。
tie 存在时，冻结 embedding **顺带冻结了 output projection** —— 这正是 paper 写的
"fine-tune all parameters in g∘f end-to-end **except for token and position embeddings**"。
tie 一断：

| | `embed_tokens.weight` | `lm_head.weight` |
|---|---|---|
| assay #1（tie 完好） | frozen | **frozen**（就是同一个 tensor） |
| assay #2…#217（tie 已断） | frozen | **trainable，每步都在更新** |

⇒ **第 1 个蛋白和第 2…217 个蛋白用的是不同的可训练参数集合**。打分本身不受影响（数值被正确复原），
但"方法"在第一个蛋白之后就悄悄变了。任何**在同一个进程里 sweep 多个蛋白并在中间 reset**
的跑法都会中招 —— ProteinGym 的 217 个 assay 正是这种跑法。

**实测影响**（本机 A4500，ESM2-35M，seed 0，同样 3 个 assay，只差这个 fix）：

| assay | 顺序 | ρ(TTT) 修复前 | ρ(TTT) 修复后 |
|---|---|---|---|
| B2L11_HUMAN_Dutta_2010_binding-Mcl-1 | #1 | 0.065641 | 0.065641（不变，符合预期） |
| GLPA_HUMAN_Elazar_2016 | #2 | 0.386654 | 0.386445 |
| PIN1_HUMAN_Tsuboyama_2023_1I6C | #3 | 0.637970 | 0.634026 |

第 1 个 assay 逐位不变、第 2 个之后才变 —— 与上面的机制解释完全吻合。

**处理方式（这是一个 deviation，必须记录）。** 我**修了 base.py 再跑复现**，而不是带着 bug 跑：
`_ttt_set_state()` 先记录参数别名关系（`_ttt_get_tied_parameters`），deepcopy 之后再把别名指回
canonical tensor（`_ttt_restore_tied_parameters`）。这样 217 个 assay 同质，且与 paper 的**方法描述**
一致（等价于"每个蛋白一个全新进程"）。回归测试 `tests/test_esm2_ttt_weight_tying.py`
—— 已验证**去掉 fix 就会 fail**、加上就 pass。仓库原有的 `test_esm2_ttt_reset.py` 抓不到它，
因为它只比较 logits（值确实复原了），不看 tensor identity。

> ⚠️ 这意味着我们复现的是 **fixed 版本**。如果 paper 的数字是"每个 assay 一个独立进程"跑出来的，
> 两者等价；如果他们也是单进程 sweep，那 paper 的 216/217 个 assay 带着这个 bug，
> 我们的数字会与之有系统性差异。**这一点在解读最终 Δ 时必须一并说明。**

## 5. Results

### 5.1 S0 — harness validation gate：**两个模型都逐位复现** ✅

自己写的 harness 从原始 assay CSV 重算全部 217 个 assay，与 ProteinGym 发布的 per-assay Spearman 比对：

| | ESM2 (35M) | ESM2 (650M) |
|---|---|---|
| assays compared | 217 / 217 | 217 / 217 |
| **max \|Δ\|** | **0.0005** | **0.0005** |
| mean \|Δ\| | 0.0002 | 0.0002 |
| \|Δ\| > 0.01 的 assay | **0** | **0** |
| **Avg. Spearman：我们 vs leaderboard** | **0.3208 vs 0.3208** | **0.4137 vs 0.4138** |
| Activity / Binding / Expression / OF / Stability | 0.3137 / 0.2907 / 0.3435 / 0.2170 / 0.4392 | 0.4254 / 0.3366 / 0.4151 / 0.3684 / 0.5233 |
| GPU 时间（全 sweep） | 12.7 min（113 fwd/s） | 2.3 h（10.7 fwd/s） |

发布 CSV 只存 3 位小数 ⇒ 舍入上界就是 0.0005。**max \|Δ\| 恰好压在这条线上，
即 217 个 assay 全部复现到发布数据自身的存储精度。**

这一步的意义不止于"harness 没写错"：**我们的 baseline 行与 paper 的 baseline 行现在是同一个数**
（paper 的 baseline 本来就是抄 leaderboard 的，见 §1），所以后面 TTT 的 Δ 可以直接与 paper 报的
+0.0196 / +0.0014 对比，不需要再讨论口径差异。

### 5.1a 达到这个结果需要发现的一件事：`MSA_start > 1` 的子区段

第一版 harness 用完整 `target_seq` 打分，35M / 650M 上**出现了完全相同的 4 个 outlier**
（KCNH2 +0.1229、SCN5A −0.0196/−0.0620、POLG_HCVJF、ZIKV）—— 两个独立模型给出同一组 outlier，
说明不是噪声。

根因：`compute_fitness.py` 在 MSA 未覆盖全序列时，会把序列截到 `target_seq[MSA_start-1:MSA_end]`
并把 `offset_idx` 设为 `MSA_start`。217 个 assay 里**只有 5 个**满足这个条件，且**全部 seq_len > 1022**：

| DMS_id | seq_len | MSA 区段 | 区段长度 |
|---|---|---|---|
| A0A140D2T1_ZIKV_Sourisseau_2019 | 3423 | 281–804 | 524 |
| KCNH2_HUMAN_Kozek_2020 | 1159 | 535–565 | **31** |
| POLG_CXB3N_Mattenberger_2021 | 2185 | 1–861 | 861 |
| POLG_HCVJF_Qi_2014 | 3033 | 1984–2089 | 106 |
| SCN5A_HUMAN_Glazer_2019 | 2016 | 1611–1642 | **32** |

按子区段打分后，**4 个 assay × 2 个模型 = 8 个数全部复现发布值到 3 位小数**：

|---|---|---|---|

### 5.2b 预算（由实测吞吐外推，待 S1-35M-seed0 实跑校准）

token-work 口径：scoring 一趟 = Σ(L+2)·min(L+2,1024)；TTT 一个 assay = 30·ags·bs·min(L,1024)·3（fwd+bwd）。

| | 一趟 scoring | TTT / seed | 每 seed 合计 | 5 seeds |
|---|---|---|---|---|
| ESM2 (35M) | 0.21 h（实测） | ~1.6 h | **~2.0 h**（含 pre+post 两趟 scoring） | **~10 h** |
| ESM2 (650M) | 2.3 h（实测） | ~4.2 h | **~6.4 h**（`--pre_score first`，只一趟） | **~32 h** |

⇒ 全保真（两个模型 × 5 seeds）≈ **44 A100-小时**，共享机上约 2 天 wall clock。

**建议方案：35M × 5 seeds + 650M × 1 seed ≈ 17 h。** 理由：
(a) 650M 声称的增益 +0.0014 落在 §1 测出的 benchmark-version 噪声底（OF 上 0.0014）之内，
    多跑 seed 只是在给一个本来就不可判定的数字加精度；
(b) paper 自己报的 seed std 是 **0.00003 (650M) / 0.00014 (35M)** —— 都极小，
    1 个 seed 已经能把均值钉到 ±0.0002；5 seeds 主要是用来**验证 std 本身**，
    这件事在 35M 那一档做就够了。

⇒ **已排 ablation：`--no_tie_restore`，35M seed 0 全 217 assay，~2.2 h**

### 5.5a seed 方差实测：paper 的 ±0.00014 是可信的（我之前的怀疑是错的）

用已完成的 35M seed 0 与 seed 1（各 217 assay）直接量：

| | 值 |
|---|---|
| +TTT seed 0 | 0.339772（gain +0.018954） |
| +TTT seed 1 | 0.339709（gain +0.018890） |
| **\|seed0 − seed1\|** | **0.000064** |
| paper 报的 5-seed std | 0.00014 (35M) / 0.00003 (650M) |

两样本的期望绝对差 ≈ 1.13σ ⇒ 由这一对反推 σ ≈ **5.7e-5**，与 paper 的 1.4e-4 同量级。
**paper 那个看起来小得离谱的误差棒站得住。**

为什么能这么小 —— per-assay 层面看得很清楚：

| | 值 |
|---|---|
| per-assay 两 seed 相关系数 | **r = 0.9999** |
| per-assay \|diff\| median / mean / max | 0.0004 / 0.0014 / **0.0164** |
| 两 seed 差异 > 0.05 的 assay | **0 / 217** |

⇒ §5.3 里那些重尾（最好 +0.5137、最差 −0.1926）**是 assay 自身的确定性性质，不是 seed 噪声**。
30 步 SGD、这个量级的 lr 下，masking 的随机性对最终权重几乎没有影响。

**对后续决策的两个直接后果：**

1. **650M seeds 1–4 不值得跑。** 我们单 seed 的 650M 增益 +0.0010 vs paper +0.0014，差 0.0004；
   若 σ ≈ 6e-5，这是 **~7σ**，seed 波动**解释不了**。再花 18.4 GPU-h 只会得到一个我们已经能
   预测到 2 倍以内的 std，且均值变化 < 1e-4 —— **不可能改变任何结论**。
2. **§5.5 那个系统偏差是铁的。** Activity −0.0051/−0.0066、Stability +0.0032/+0.0070，
   对照 σ ≈ 6e-5 是 **50–100σ**。所以 GPU 时间应该花在 weight-tying ablation 上，而不是更多 seed。
