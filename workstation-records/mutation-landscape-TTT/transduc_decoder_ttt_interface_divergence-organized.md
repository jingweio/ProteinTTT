## 1. 立题

### 1.1 要验证的假设

预训练 ProteinMPNN 的 decoder **没有把「突变位点离 partner 多近」用起来**（摸底记录已证实）。
假设：在 test time 用一个**不需要 label** 的目标把它逼出来，排序能力会提升。

**transductive**（看得到该 assay 的 mutant 序列，**看不到 label**）、**只微调 decoder、冻结 encoder**。

### 1.2 这个实验能回答什么、不能回答什么

| | |
|---|---|
| **能回答** | 「把界面先验**训进 decoder**」是否比「**事后加一个平移**」更好 |
| **不能回答** | 界面先验本身值多少钱 —— 摸底记录已回答（LOAO +0.0648） |

**⇒ 对照臂是 rescoring 规则，不是预训练基线 0.3903。**

## 2. 框架

### 2.1 一个必须先处理的结构性问题

「最大化两组分数分布的差异」**不加约束**时，全局最优是让分数**变成界面特征的一个函数** ——
组内信息全丢。那时 Spearman 就等于「用界面特征单独当预测器」：

| 分数塌缩成 | 14-assay Spearman |
|---|---:|
| 预训练基线 | 0.3903 |
| 纯二值界面标签 | 0.2068 |
| 纯连续距离特征 | 0.2564 |

**⇒ 无约束版本的最优解比起点还差 0.13–0.18**，与已被否证的 WT-likelihood 目标是同一类失效。
所以目标必须写成**散度 + 锚**。

### 2.2 系统

```
L(θ) = pearson( w̃ , s̃ )  +  λ · ‖ s_θ − s_frozen ‖² / var(s_frozen)
       └── 散度：推向「越近界面分越低」      └── 锚：不许离预训练太远
```

| 符号 | 定义 | 训练时可见 |
|---|---|---|
| `s_θ(v)` | 微调后的分数，**与评测用的是同一个函数**（官方 BindingGYM 口径） | — |
| `s_frozen(v)` | 冻结模型的分数 | ✅ |
| `d(v)` | 突变位点到**另一个 entity** 的最小重原子距离（WT 复合物算出） | ✅ label-free |
| `w(v)` | 界面先验 = `AGG_i f(d_i)`，batch 内标准化 | ✅ label-free |
| `y(v)` | 真实 DMS_score | ❌ 训练绝不可见，只在评测用 |
| `λ` | 锚的强度，**逐 assay 扫**（用户 2026-09-12 决定） | — |

**`λ` 就是摸底记录里那个 `c` 的化身** —— 它控制「往界面方向推多远」。
`λ→∞` 回到预训练模型，`λ→0` 塌缩到 0.2564；**中间有没有峰，就是本实验要测的**。

> **优化 Pearson、评测 Spearman** 是一个代理间隙（Spearman 不可微），如实记在这里。

### 2.3 🔴 一个预先写下的理论点：L2 锚会让最优解退化回 rescoring 规则

若把 `s` 当作不受网络限制的自由变量，`L` 的最优解就是沿 `w` 方向的一个平移 ——
**那正是 rescoring 规则**。

⇒ **TTT 唯一可能赢的原因，是 decoder 表达不出任意分数向量**，
因而只能用「逐位点的、结构相关的」方式去逼近这个方向。**优势来自表达受限，不来自目标函数。**
这条给出了 **D-1** 的判据：把 `Δs = s_θ − s_frozen` 对 `c·w` 回归，R² 接近 1 ⇒ TTT 无意义。

### 2.4 评测协议与门槛

**14 个 assay**、per-assay Spearman、未加权均值。

| 臂 | `c` / `λ` 怎么选 | ρ |
|---|---|---:|
| 预训练基线 | — | 0.3903 |
| rescoring，`max + exp(−d/5Å)` | LOAO | 0.4551 |
| rescoring，`max + exp(−d/5Å)` | **oracle** | **0.4689 ← E-1 的门槛** |
| rescoring，`sum + exp(−d/5Å)` | oracle | 0.4850 |
| rescoring，`sum + 1/(1+d/20)` | oracle | **0.5074 ← 该族上确界** |

🔴 **门槛不是一个数**：本阶段 `λ` 是逐 assay oracle 选的，所以对照的 `c` 也必须是 oracle；
而**特征必须两边相同** —— TTT 用哪个 `w(·)`，就比哪个 `w(·)` 的那一行。
（早先把 0.4850 写成「本阶段门槛」是错的，已更正。）

## 4. 结果

### 4.1 前置实验 ①：`w(·)` 的**聚合方式**比 `τ` 重要得多

| 聚合 + 形式 | oracle `c*` | LOAO 共享 `c` |
|---|---:|---:|
| `sum` + `exp(−d/5Å)` | 0.4850 | **0.4599** |
| `sum` + `exp(−d/3Å)` | 0.4737 | **0.4582** |
| `mean` + `exp(−d/8Å)` | 0.4823 | **0.4572** |
| `max` + `exp(−d/5Å)` ← 摸底/E-1 用的 | 0.4689 | 0.4551 |
| *置换距离的 null（同样 best-of，3 seed）* | *0.3917* | *0.3903* |

- **`τ` 几乎不重要**：前 5 名的 `τ` 从 3 Å 到 12 Å，差别 < 0.004。
- **聚合才重要**：`max`（只看最近的那个突变位点）→ `sum`（每个位点都记一笔），oracle **+0.0161**。
  增益**全部**来自 9 个多点突变 assay —— 5 个单点突变 assay 的天花板在两种聚合下**逐位精确相等**
  （k=1 时 `max` 与 `sum` 是同一个数）。
- **null 干净**：置换距离后 LOAO 增益恰好 **0.0000**（3 seed 全是）⇒ 63 选 1 没有过拟合。

> 🔴 **这是第二次「零 label、零 GPU」把门槛推高。** 摸底里的 `τ=5 Å` 本身没问题，**选错的是聚合**。

### 4.2 两个门都过了

| | |
|---|---|
| **G-B** | 缓存 encoder 的可微实现 vs 官方 `compute_fitness_multi_pdb.py`，**最大相对偏差 3.0e-7**（float32 累加量级）。含带 Kabat insertion code 的 4ZFG。 |
| **G-A** | 线性探针读冻结的 node embedding `h_V`：**within-assay AUC 0.890、LOAO 0.915**。信息在，且**跨复合物共享**（LOAO 比 within 还高，因为训练数据多 13 倍）。 |

**⇒ 「decoder-only 可能表达不出来」这条风险解除。**
但**连续距离的可迁移性明显弱于二值接触**（ρ 0.404 vs 0.483）—— TTT 要学的恰是梯度，值得记着。

### 4.3 E-1：目标函数**有操作窗口**，8 个 assay 的均值**刚好越过** oracle 天花板

#### 实验配置

| 项 | 取值 | 说明 |
|---|---|---|
| 可训练参数 | decoder 的 3 层 `DecLayer` + `W_out` = **695,445 / 1,660,485 (41.9%)** | encoder、embedding `W_s` 全部冻结 |
| optimizer / lr | **Adam / 1e-4** | 既往实测 lr ≥ 1e-2 会直接摧毁排序（0.705 → 0.388）；3e-5 / 3e-4 **尚未扫** |
| **max steps** | **300（固定预算）** → 🔴 09-14 判定**太少**，E-4 正在测 3000 | ⚠️ **不是「训到收敛」**（见下面「怎么选最终模型」），而且 **transductive setting 下连 target mutant 都没吸完**：300 步的覆盖率中位 90.7%，但 `GB1` 只有 **25.2%**、`KRAS_PICK3CG` 26.8%、`SARS2-RBD_ACE2` 33.8%。要 14 个全部 ≥95% 需 **3,091 步**，≥99% 需 **4,751 步**（都被 `GB1` 卡住） |
| **等效 epoch** | **0.29（GB1）~ 23.8（PSD95）** | `steps × batch / n`，**跨 assay 差 80 倍**，训练量不可比 |
| batch | `clip(3e8/(L·48·256), 8, 128)` → 实际 **26**（`ACE2`, L=931）**~ 128**（`PSD95`, L=120） | 显存约束（activation ∝ `L × 48 neighbors × 256 hidden`）。batch **不是均匀抽**：**variant 级**的 `w`（`max`/`sum` 聚合之后）按该 assay 自己的 20/40/60/80 **分位**切 5 档，每步每档抽 `bs//档数` 个拼成 batch —— 因为 `L_div` 是 **batch 内**的 Pearson，`w` 没跨度的 batch 给不出梯度方向。分位而非等宽：`w = exp(−d/5Å)` 到不了 0.6（那是 `d = 2.55 Å`），等宽切法上面两档恒空 |
| 抽样方式 | **batch 内无重复**（每档 `randperm[:per]`） | 🔴 09-14 改：重复样本会在 `L_div` 的相关与 `L_anchor` 的均值里各算两次。**已跑的 8 个 assay 是有放回的**（`5A12` 每档每步 ~1.2 个重复、`PSD95` ~1.0、其余 <0.2） |
| 训练时的解码顺序 | 每步从官方 5 个里**随机抽 1 个**，**整个 batch 共用这一个**；锚对的是**同一个顺序**的冻结分数 `s_frozen[v, m]` | 否则锚会去惩罚解码顺序噪声。5 个顺序在建 context 时一次抽定（seed=1，与官方同一套；G-B 已验证逐行复现） |
| **λ 选参口径** | 排 λ 的 ρ **只用 1 个解码顺序**（`--sweep_eval_M 1`），**训练一律从 5 个里抽** | 🔴 2026-09-14 定为标准口径：只让**读数**变便宜，**训练 regime 不动** |
| 最终评测 | **M=5**（官方口径），全量 variant | 与 zero-shot 基线逐行同函数（G-B 已验证）；`λ*` 选出后同 seed 重训、按 M=5 出数 |
| 特征 | 已跑的 8 个用 `w = max_i exp(−d_i/5Å)`；🔴 09-14 起改用 **`sum`** | `max` 是**未调**的那个 ⇒ 对照 0.4689 一档；`sum` 对照 0.4850。**5 个 assay 是纯单突变（`n_mut ≡ 1`）⇒ 两者恒等**，只有 9 个多突变 assay 会变 |
| seed | 1（与官方 zero-shot 同） | 多 seed **未做** |

> ⚠️ **`3e8` 这个常数是先验写下的，2026-09-14 才实测（M-1 / M-1b，全 14 assay）。**
> peak reserved ≈ **`8.8e-4 GiB × bs × L`**（46 个测点，L 从 56 到 1107，离散 8.2~9.0e-4）
> ⇒ 可用 70 GiB 时 **`bs_max ≈ 7.9e4 / L`**，而公式给的是 `2.4e4/L`，**保守 3~4 倍**。
> 小 batch 还更慢（L=120 每样本：bs=32 是 3.5 ms，bs=64~384 稳定 ~1.0 ms）⇒
> **大 `L` 的 assay 一直在白付 `L_div` 的估计噪声，而 `ACE2` 恰好是 8 个里最差的那个。**
>
> 逐 assay 可行性（70 GiB 预算）：**`bs=128` 9/14 安全、2 个勉强（L≈650）、3 个不行（L ≥ 791）；
> `bs=256` 只有 L ≤ 262 的 7 个；`bs=512` 只有 3 个。想 14 个 assay 用同一个 batch，
> 上限是 `bs = 64`**（被 `KRAS_PICK3CG`, L=1107 卡住）。统一到 128 需要 bf16 或对 decoder 做
> gradient checkpointing，两者都会改数值/时间口径。明细见 tracking §1.2。
> 改 batch 会改等效 epoch、与已跑的 8 个不可比，属口径决定，见 §6 条 2。
>
> ⚠️ **分位档会塌。** `w` 有并列时 `np.quantile` 的边界会重合：`CD19` 只有 4 档、
> `5A12` 只有 **2** 档（`[124, 0, 0, 0, 819]`）⇒ 这两个 assay 的「每档 `bs//5`」不成立，
> 实际是 12 和 18，等效 epoch 也随之变成 3.71 和 **11.45**。其余 12 个 assay 都是满 5 档且均衡。

#### 🔴 怎么选最终模型（这一步目前**完全没有 label-free 的成分**）

1. **训练内部不选模型** —— 跑满 300 步、**不做 early stopping**、直接拿**最后一步**的权重。
   方案要求的是「训到收敛」，实现成了固定步数，**所以 λ 与步数现在是混淆的**
   （`l_div` 在 λ=0.03 下第 299 步仍是最负值、还在降）。
   ⇒ **下面的 `λ*` 应读作「300 步预算下的最优锚强度」，不是最优锚强度本身。**
2. **λ 用该 assay 的 DMS label 选**（取 Spearman 最高的那个）⇒ **这是一个 oracle 选择**，
   所以对照臂的 `c` 也必须是 oracle（§2.4）。**两边 label 用量相同，这一点是公平的。**
3. **没有任何 label-free 的模型选择信号**（pLDDT 的类比仍未找到）⇒ 现阶段**不可部署**，
   这与 `c` 的问题是同一个（见 §7.4）。

> 一律按 `--M` 建，**每个 λ 的训练完全相同**（都从 5 个顺序里抽），只有用来**排序 λ** 的 ρ 少读
> 几个顺序。于是 `λ*` 与最终模型处在**同一个训练 regime** —— 而上面 4 行的 `λ*` 是在 1-order
> 训练下选出来、却交给 5-order 训练去用的。新口径还省掉一次 context 重建和一遍 frozen-score
> （旧口径算 `n×1 + n×5`，新口径只算 `n×5`），**比它替代的东西更便宜**。

#### 曲线形状说明了什么

- **`λ→∞` 一侧全部单调回到基线** ⇒ 与 §2.1 的预期一致。
- **`λ→0` 一侧**：`GB1` 塌缩到 **−0.3020**（比预训练差 0.30）、`5A12` −0.0798，
  正是 §2.1 预言的退化（分数变成界面特征的函数）⇒ **峰是真峰，不是网格截断。**
- ⚠️ **`ACE2` 的 λ\* = 0.001 仍是所测最小值、曲线还在上升 ⇒ 它还没到头**，
  −0.0648 仍是被低估的。它需要的位移最大（`c* = −1.95`），锚必须极弱。
- **`λ*` 主体集中**：7/8 落在 `[0.03, 1]`，只有 `ACE2`(0.001) 与 `5A12`(10) 两个外点，
  而两个都能解释 —— `5A12` 的 headroom 只有 +0.0003（**本来就没东西可赚，λ→∞ 才是对的**），
  `ACE2` 需要的位移最大。
  ⚠️ 但 **`λ*` 与 `|c*|` 的 Spearman 只有 −0.296**（n=8，不显著）⇒
  **`L_anchor` 除以 `var(s_frozen)` 这个归一化，没有真的把 λ 做成跨 assay 可比的量**，
  而那正是它的设计目的。「共享一个 λ」目前只是**看起来**有希望，没有机制上的保证。

#### 一个顺带发现：**训练时用几个解码顺序也是一个旋钮**

`GB1` 在 **M=5 训练**下（E-1，λ=0.3）拿到 **0.5645**，比 **M=1 训练**下（λ=1）的 0.5577 **高 0.0068**。
两者是不同配置，**表里报的是 M=1 那次**（因为它的 λ 覆盖更全）。
这 0.0068 正是旧 `--sweep_M` 口径的代价。新口径把**训练 M 固定为 5**、只缩读数，这个混淆从此不存在 ⇒ **「训练 M」不再是待扫项，已定为 5。**

#### `sum` vs `max`：把先验做好**不等于**把 TTT 做好

实验 ① 已证 `sum` 把**零 label 的 rescoring 天花板**从 0.4689 抬到 0.4850。
但在 TTT 这一层，现有 5 个 assay（同 λ 网格、同 300 步）给的是另一幅图：

|---|---:|---:|---:|---:|---:|---:|---|
| `PSD95_CRIPT` | 1.00 | 0.5579 | 0.5567 | 0.5579 | 0.5567 | **0** | +0.0011 → +0.0011 |
| `PSD95_Tm2F` | 1.00 | 0.2408 | 0.2592 | 0.2408 | 0.2592 | **0** | −0.0184 → −0.0184 |

2. **仅有的两个可比行方向相反**（`5A12` +0.0278 / `CD19` −0.0285），而且**按各自天花板算，`sum` 反而更差**
   （均值 +0.0005 → −0.0097）—— 因为 `sum` 把**门槛**抬得比把 TTT 抬得多。
   ⚠️ n=2，且这两个恰是 headroom 最小（`5A12`）和唯一 `sum` 会**降低**天花板（`CD19`）的极端。
   ⇒ **不足以下结论**，E-4 正在多突变主力（`GB1` / `KRAS_RAF1-RBD`）上补。

### 4.5 E-3 置换 null：**增益的 81% 归于界面先验**

把 `d` 在 assay 内**随机置换**后跑完全相同的一套 TTT（同一 λ 网格、同一 `sweep_M`、同一步数）。

置换的对象是**逐 variant 聚合之后**的 `w = max_i exp(−d_i/5Å)`：先照常算出 `w`，再在 assay 内
把 **variant ↔ `w` 的配对**打乱（`np.random.default_rng(seed=1).permutation(n)`）。于是 `w` 的
**边缘分布逐值不变**（同一个 multiset）、5 档分层的档内样本数不变、λ 网格 / 步数 / batch /
解码顺序 / `s_frozen` 全部逐位不变 —— **唯一被破坏的是「哪个 variant 配哪个界面特征」**。
⚠️ 每个 assay 只抽了**一次**置换（不是一个 null 分布），3 个 assay ⇒ **n=3**。

这是唯一能区分「学到了界面」与「TTT 这个动作本身的扰动 / 正则效应」的实验。

| assay | zero-shot | **真实 `d`** | **置换 `d`（null）** | 真实增益 | null 增益 | **净** | null 占比 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `GB1_IgG-Fc` | 0.5005 | **0.5577** (λ=1) | 0.5149 (λ=3) | +0.0572 | +0.0144 | **+0.0429** | 25% |
| `KRAS_RAF1-RBD` | 0.4413 | **0.6736** (λ=0.3) | 0.4915 (λ=0.003) | +0.2324 | +0.0502 | **+0.1821** | 22% |
| `PSD95_CRIPT` | 0.3672 | **0.5559** (λ=0.1) | 0.3921 (λ=3) | +0.1887 | +0.0249 | **+0.1638** | 13% |
| **均值** | | | | **+0.1594** | **+0.0298** | **+0.1296** | **19%** |

**🔴 `null` 越过 oracle 天花板：0/3。真实：2/3。**

**三条读法：**

1. **null 确实会涨一点**（+0.0298）—— TTT 本身有轻微正则效应，**这是真的，必须承认**。
2. **但它只占总增益的 19%**，**81% 归于界面先验**。
3. **决定性的一条：null 一次都没越过 rescoring 天花板，真实臂越过了 2/3。**

## 5. 结论

### 5.1 已经能说的

1. **目标函数有操作窗口。** 两端都按预言出现（`λ→∞` 回基线；`λ→0` 塌缩到比基线更差，
   `GB1` 塌到 −0.3020）。**「与 WT-likelihood 同类失效」这个最可能的结局被排除了。**
2. **增益主要来自界面先验，不是 TTT 的扰动效应。** 置换 null 只拿到 **19%**，
   且 **0/3 越过 rescoring 天花板**，而真实臂 2/3 越过。
   λ 曲线在同一根轴上**符号相反**，这比均值更硬。
3. **TTT 学到的东西有约 1/3 不是标量能表达的**，而赢天花板的那部分正来自它 ——
   与「优势来自 decoder 表达受限」的预言一致（§2.3）。
4. **界面先验的价值会被便宜的方法持续吃掉。** 改一个聚合函数（零 label、零 GPU）
   就把对照臂从 0.4689 推到 0.4850，族上确界 0.5074。
   ⇒ **任何 TTT 结果都必须对着「当前最好的便宜方法」报，而不是对着基线。**

### 5.2 还不能说的

**不能说这套方法「可用」** —— 它现在还**不可落地**，缺的不是效果而是**选参**：

1. **`λ` 靠该 assay 的 DMS label 选**，且**训练内部完全没有 label-free 的模型选择信号**
   （跑满 300 步取最后一步）。这与摸底阶段 `c` 的问题**是同一个** ——
   已测 10 个静态特征，9 个不如常数，最好的只拿回 28% 且过不了 BH 校正。
   **pLDDT 的类比至今没找到。**
2. **`λ*` 目前也不可靠** —— 它与 `|c*|` 的 Spearman 只有 −0.296，说明
   `L_anchor / var(s_frozen)` 这个本该让 λ 跨 assay 可比的归一化**没有起作用**。
   「7/8 落在 `[0.03, 1]`」目前只是**观测**，没有机制保证。

### 5.3 边界（读上面任何数字时都要带着）

1. **8 / 14 个 assay 有 TTT 结果，其中只有 3 个有 null 对照。**
   而且这 8 个**不是随机抽的**（先挑了小的和有代表性的）。
   ⚠️ **剩下 6 个里有 3 个 KRAS，恰好是 headroom 最大的那批**（+0.10 ~ +0.13），
   与目前赢最多的 `KRAS_RAF1-RBD` 同家族 ⇒ **现在报的任何均值都不是最终值。**
2. **均值 +0.0019 是「刚好越过」，不是「明显越过」**，且被 `ACE2`（−0.0648）压着，
   而 `ACE2` 的 λ 网格**仍未到头**（λ\* 落在最小值且曲线还在升）。
3. **训练预算不可比**：同样 300 步，`GB1` 只看 0.29 个 epoch、`PSD95` 看 23.8 个；
   且 `l_div` 在小 λ 下 300 步**没收敛** ⇒ **`λ*` 只能读作「300 步预算下的最优锚强度」。**
4. **`E-1` 用的是未调的 `max` 特征**，所以对照 0.4689；实验 ① 已证明 `sum` 更好。
   两边必须同特征，**不可混引**。
5. **单 seed（seed=1）**，多 seed 未做。GPU 非确定性实测 ≈ 3e-6，远小于任何被引用的效应。

## 7. 深入优化模型设计（用户 2026-09-13 提出的方向 + 即时验证）

> 想法本身：pooling multi-site 只是一条轴；另一条是**把距离映射成与 DMS_score 更相关的特征**，
> 这样更适合做 regularization，**甚至可能解决 `corr()` 的方向约束问题**。

### 7.1 两条轴是**独立**的，杠杆来源不同

| | 是不是 `d` 的单调变换 | 后果 |
|---|---|---|
| **换形状** `f(d)` | **是** | `Spearman(f(d),·)` 恒定不变 ⇒ 改不动任何**秩层面**的量 |
| **换聚合** `AGG_i f(d_i)` | **否**（`sum` 不是任何单个 `d_i` 的函数） | 秩也会变 |

⇒ **换形状有杠杆，不是因为特征「更像真值」，而是因为加性 rescoring 与 Pearson 对形状敏感** ——
而那恰好就是我们用的两个东西。实测：在 pooling 完全失效的 5 个单点突变 assay 上，
7 种形状之间的 oracle 差距**中位 0.0285、最大 0.1180**，且**每个 assay 的最优形状不同**。

### 7.2 🔴 方向问题基本由特征决定，不是模型的病

| 特征 | `\|corr(w,y)\|` 中位 | **起点符号与真值一致** | rescoring LOAO |
|---|---:|---:|---:|
| `max` + `exp(−d/5Å)`（E-1 在用） | 0.263 | **9/14** | 0.4551 |
| `sum` + `exp(−d/5Å)` | 0.295 | 10/14 | **0.4599** |
| **`sum` + `exp(−d/20Å)`** | **0.349** | **13/14** | 0.4047 ← 61/63 名 |

4 个 KRAS / GB1 **全部被修好**：`corr(w,s_frozen)` 翻成负，而 `corr(w,y)` **不但没翻、还更强**
（`KRAS_RAF1-RBD` −0.359 → −0.444）。唯一例外 `hYAP65` 的真值方向本来就 ≈0。

**⇒ 起点 13/14 正确意味着 loss 只需「加强」而不需「掰方向」，
那正是方向不感知目标（`−pearson²`）能正确工作的前提。**
早先「方向不感知在这批数据上更危险」的结论**绑定在旧特征上，必须重测**（→ §6 的 F-3）。

### 7.3 真正的发现：两个角色要的不是同一个特征

`sum + exp(−d/20Å)` 做 **rescoring 排 61/63**，却是**最好的 regularizer**（两个指标都最好）。
⇒ **「最适合做加性平移的特征」≠「最适合做相关性正则的特征」。**
后续设计里这两处**可以、而且大概应该**用不同的 `w(·)`（→ §6 的 F-2）。

### 7.4 一条预先写下的风险

把「形状」变成可学的（单调样条 / 小 MLP on `d`）**会再加一个需要 label 才能选的旋钮** ——
与 `λ` / `c` 是同一类问题（摸底记录已给出否定结论：静态 WT 特征里没有 pLDDT 的类比）。
**除非同时给出 label-free 的选法，否则它只抬高 oracle 上界、不让方法更可部署。**
